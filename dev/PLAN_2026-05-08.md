## Sequence forward — ordered by safety + dependency + value

### Tier A — Foundations (next 3 sessions)

```
1. σ.3  GitHub backup via Claude Code              ~ 1 session · LOW
        Walk user through Claude Code install. Initialize repo,
        create private GitHub repo on user's account, push entire
        project. From this point: git pull at start of each
        session; git push at end. No more zips.
        Deliverables: project on github.com (private), session
                      handoff docs updated to mention git workflow.
        Note: claude can create private repos on user's behalf
              and push code; cannot make repos public, add
              collaborators, or change access — those changes
              are user-side per safety policy.

2. υ.7  Pluggable fetcher config                   ~ 1 session · LOW
        content/sources/_fetchers.json — declarative URL +
        parser-kind list. Lets fetch_sources.py read its source
        list from config rather than Python constants.
        Deliverables: _fetchers.json schema, loader, migration
                      of existing NAVES_CANDIDATE_SOURCES into it,
                      tests for the schema.

3. υ.1  /sources console upgrade                   ~ 1 session · LOW
        Real source-management page: status grid, "Fetch this" /
        "Fetch all" buttons, paste-a-URL override, drag-and-drop
        file upload to drop a pre-built JSON directly into
        content/sources/. Permanently closes source-fetch friction.
        Deliverables: console route, API endpoints, drag-drop
                      upload validation reusing the §9 binary-asset
                      pattern, tests.
```

## Working agreements

- Saves are explicit, not automatic. "Save" / "Slim" / "Full" only.
  Once σ.3 ships, "save" becomes "git push" — no zip.
- "Continue" / "push" advance to the next phase; never trigger a save.
- Every phase ship updates: code + tests + CHANGELOG + SESSION_STATE
  + IN_FLIGHT marker + Tier-1 audit.
- Phases reference scope-addendum sections for spec, not phase letter
  for ordering. Logical sequence > alphabetical.
- §13 (topic-shift audit) and §14 (state-uncertainty audit) protocols
  apply unconditionally. Both have caught drift in the last 2 sessions.
