**Date:** 2026-05-09 — full restructure after the v1.0 candidate
became shippable. Replaces `dev/PLAN_2026-05-08.md` (now in
`dev/archive/`).

**Status:** active master sequence. Companion docs: every

**Why this restructure:** the 2026-05-08 plan was structured around
the path TO v1.0. Every phase from Tier A through Tier C shipped

floor was crossed by 26K notes. The plan is no longer a road; it's

restructure surfaces:

  - **What's already shipped** (so future Claude doesn't re-scope it)
  - **Explicit `Depends:` and `Unblocks:` per open phase** (was
    implicit prose; the linter can verify the graph now)

    bundled — bandwidth-aware per §3.6)

    session bandwidth
  - **Track grouping** (Release / Short / Medium / Long / Hardening
    / User-side / Parked) instead of Tier A/B/C — surfaces the
    right next move at any session-bandwidth budget
  - **Pre-session ordering recommendation** in §6 — "if the next
    session is X minutes / focused on Y, do Z"

## 3. Track structure

Six tracks. Each open phase belongs to exactly one. Tracks order
work by how it competes for bandwidth, not by Greek-letter family.

| Track | Description | Session cost |
|---|---|---|
| **RELEASE** | One-time motion to declare v1.0 shipped | 0.5-1 session |
| **SHORT** | 1-session phases; bandwidth-cheap; bundle by file overlap | 1 each |
| **MEDIUM** | 1-2 sessions; needs a spec read or spec write | 1-2 each |
| **LONG** | Multi-session; strategic features needing infrastructure | 2+ |
| **HARDENING** | Audit-style; runs alongside any track | 0.5-1 each |
| **USER-SIDE** | No my-session bandwidth; user runs externally | 0 from me |
| **PARKED** | Design call needed before implementing | gated |

A phase with multiple sub-phases (e.g. ψ.7-A + ψ.7-B) lives on the
same track unless one explicitly waits.
