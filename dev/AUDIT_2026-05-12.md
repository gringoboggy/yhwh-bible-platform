### 4b. ξ.18.x style-src tightening — pinned but not specced

ξ.18's `_csp_with_nonce` docstring + the test pin
`test_style_src_keeps_unsafe_inline` document the deferred
style-src tightening. But there's no addendum capturing the
trade-off:

- Option A: Move off Tailwind Play CDN → bundle Tailwind →
  every style is in `<style>` tags we control → nonce them.
  Cost: build step (conflicts with §6.3 "no build step").
- Option B: Hash-based CSP for style-src (sha-256 hashes of every
  legitimate `<style>` block). Brittle against Tailwind version
  bumps; needs CI regeneration on every Tailwind release.
- Option C: Stay with 'unsafe-inline' for style-src; accept the
  XSS surface is style-only (no script execution); document the
  threat model.

Recommend writing a short ξ.18.x addendum so the choice is
informed when it's eventually made.
