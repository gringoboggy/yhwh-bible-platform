## 1. F-DEEP3-1 — editions.yaml content-pollution leak — ROOT-CAUSED + FIXED + VALIDATED (WARN, actioned)

**Symptom (flagged at the τ.7.x.q/r ship close):** running the
full suite under `pytest -n auto` left `content/editions.yaml`
git-modified with a leaked `book_toc_ornament: cross_latin` line
under `catholic-study`.

**Root cause (subagent C + spot-verified):** NOT the DEEP-2
F-DEEP2-1 missing-isolated-path pattern. `api_save_edition_meta`
(`scripts/api/editions.py`) is structurally un-isolatable — it
hard-codes the live `content/editions.yaml` path. The save-meta
round-trip tests defend via backup + `finally`-restore. The leak
is the **second-order LRU-cache-pollution class documented
verbatim at `tests/test_scripts.py:11172-11180`**:
`api_save_edition_meta` populates BOTH the `config.load_editions`
AND the `matrix.compute_matrix` LRU caches with the mutated edition
record. Six `finally` blocks restored the file + cleared ONLY
`config.load_editions` — leaving the mutation live in
`compute_matrix`'s cache. A later same-run test
(`TestOmega16EditionSnapshots`) reads that still-cached record and
re-persists it to `content/editions.yaml` via `_dump_edition_record`
(unquoted YAML) before the next clean read. The proven-good
sibling `test_save_edition_meta_accepts_valid_plan_ids`
(`tests/test_scripts.py:11201-11205`) clears BOTH caches; the 6
defective blocks omitted `matrix_mod.compute_matrix.cache_clear()`.

**FIX (this pass):** added
`from scripts.core import config, matrix as matrix_mod` +
`matrix_mod.compute_matrix.cache_clear()` to ALL **6 byte-identical
defective `finally` blocks** in `tests/test_scripts.py` (the actual
leaker `test_save_edition_meta_accepts_book_toc_ornament` + 5
latent siblings of the same class), with a class-accurate
explanatory comment. This mirrors the canonically-documented
proven-good sibling; it is purely-additive teardown hygiene (a
`finally` cache-clear cannot change a passing test's assertions),
so fixing the whole class is zero-risk — matching the DEEP-2
philosophy of fixing ALL instances of a defect, not only the one
that happened to fire.

**Investigation note (systematic-debugging):** the first post-fix
check reported "FIX INSUFFICIENT" because `git status` still
flagged editions.yaml. Per `superpowers:systematic-debugging`
Phase-1 (gather evidence; read carefully) this was investigated
rather than re-patched: `git diff --ignore-cr-at-eol --stat` is
**EMPTY** — the `book_toc_ornament` content leak is GONE. The
residual flag is F-DEEP3-2 (benign CRLF), not a content leak. The
"insufficient" reading was a premature `git status` (vs `git diff`)
misread; the content fix is sound.

**VALIDATION:** from a CLEAN baseline, post-fix, under the leak-
trigger conditions: serial `TestEditionMeta + TestOmega16Edition
Snapshots` (206 passed) → content diff EMPTY; `-n auto`
`test_scripts.py` (960 passed) → content diff EMPTY (modulo the

## 2. F-DEEP3-2 — editions.yaml CRLF line-ending flip on Windows test rewrites (INFO, deferred)

After the content fix, `content/editions.yaml` still shows in
`git status` mid-test-run on Windows. Evidence: committed file = 0
CR (LF, git-normalized via `.gitattributes` `* text=auto`);
post-test working copy = 431 CR (CRLF). `git diff
--ignore-cr-at-eol --stat` is empty → **zero content change**;
`git add content/editions.yaml` → `git status` CLEAN (git's
`text=auto` normalizes CRLF→LF on add). So this **never reaches a
commit**, has zero content/semantic impact, and is editions.yaml-
specific (no other tracked YAML flips). Root cause: the
`api_save_edition_meta` / `_dump_edition_record` writer emits the
host newline (Python Windows text-mode `\n`→`\r\n`) where the repo
convention is LF; pre-existing Windows-dev behavior, NOT introduced
by τ.7.x.* or the F-DEEP3-1 fix. **Deferred** (not fixed this
pass): it is benign git-normalized noise, not a data defect;
making the editions writer emit explicit LF (`newline="\n"`)
touches production file-write code with its own test surface and
belongs in a dedicated ω-hygiene phase, not an audit-fix. Its only
real cost is having twice masqueraded as a content leak in
`git status` — now precisely characterized so future ships read
`git diff` (content), not `git status` (CRLF-noisy on Windows),
for editions.yaml.
