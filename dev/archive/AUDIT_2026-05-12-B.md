## 3. New patterns established this session

### 3a. SEED + ETL.x decomposition (formalized via χ.2-5 cluster)

Every χ.2-5 SEED ship documented its forward ETL.x sub-phase
(χ.2.x, χ.3.x, χ.4.x, χ.5.x). The pattern: SEED ships
infrastructure + 12 representative entries + forward-reference
the full ETL.x for user-side completion. PLAN's §χ.2-5 table
now uses a "SEED ✓ / .x open" status column rather than binary
open/closed.

**Why this matters going forward:** future cluster work (the
γ.4.x sub-phases, the τ-cluster's full translation ingests,
the χ-cluster's full ETLs) can ship as SEED → wave-1 → wave-2
→ wave-N with each wave being a single-session ship. This
addresses what AUDIT_2026-05-12 §4d flagged ("IN_FLIGHT chain
bloat") by giving structure to multi-wave ships.

### 3b. Anti-fabrication pin (γ.4.1.C)

γ.4.1.C's test class added `test_no_coverage_in_lost_chapters_8_through_10`
which explicitly asserts that the corpus must NOT contain any
Cyril-on-John entries for chapters 8-10 (Cyril's Books VII-VIII
are LOST in the manuscript tradition; any such content would be
unsourceable fabrication).

**Why this matters going forward:** AI-assisted paraphrasing
sessions can drift into "filling in gaps" with plausible-
sounding content that has no manuscript basis. The anti-
fabrication pin makes this *test-detectable*. **Recommend this
pattern be added to every future Father-specific wave** when
manuscript-tradition gaps are known.

### 3c. Year-range anti-merge pin (χ.2 / χ.3 / χ.5)

Each commentary corpus added a per-entry year-range assertion:

- χ.2 (Matthew Henry): every entry year in 1700-1721.
- χ.3 (Calvin): every entry year in 1540-1564.
- χ.5 (Rashi): every entry year in 1070-1105.

**Purpose:** prevent accidental cross-tradition merging. If
someone adds a post-Calvin entry to reformation_commentaries.json,
the test fails loud; if someone adds a non-Henry entry to
protestant_commentaries.json, same outcome.

**Why this matters going forward:** as future χ.x.x ETLs land
new voices (Spurgeon for comm-protestant, Luther for
comm-reformation, Maimonides for comm-rabbinic), the year-range
pins need to be relaxed deliberately in the test — preventing
silent voice-creep into the original SEED.

### 3d. Per-tradition title prefix (χ.2 → χ.5)

Each commentary detector adds a distinct draft_title prefix:

- χ.2 ProtestantCommentaryDetector: "Protestant — {commentator}"
- χ.3 ReformationCommentaryDetector: "Reformation — {commentator}"
- χ.4 CatholicCommentaryDetector: "Catholic (Catena Aurea) — {father}"
- χ.5 RabbinicCommentaryDetector: "Rabbinic — {commentator}"

This gives the ψ.8 cross-denominational popup natural chip
labels without needing per-edition customization. Pattern is
now consistent across all six tradition kinds (γ.3 patristic +
γ.4 ethiopian + χ.2-5).

### 3e. CRLF/LF warnings on every save

Every save.cmd invocation this session generated CRLF→LF
warnings on `content/.refactor_log.yaml`, `content/editions.yaml`,
`content/notes/gen.py`, `dev/IN_FLIGHT.md`, `dev/PLAN_2026-05-09.md`.
This is benign (Git auto-handles via `core.autocrlf`) but creates
visual noise in every save output.

**Recommendation:** add `* text=auto eol=lf` to `.gitattributes`
to silence the warnings, OR document that the warnings are
expected. ~5 minutes to fix; doc-only.
