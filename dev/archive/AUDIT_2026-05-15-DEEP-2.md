### NEW findings — WARN, both ACTIONED this pass (2)

#### F-DEEP2-1 — `content/.refactor_log.yaml` test-pollution leak — ROOT-CAUSED + FIXED

The "persistent unrelated `.refactor_log.yaml` change" flagged across
the τ.7.x.j/k and τ.7.x.l/m ship commit messages was **not**
in-progress kind-rename work — it is a **test-isolation bug**.

`tests/test_refactor.py` had two tests —
`test_apply_rewrites_notes_files_position_4_only` and
`test_apply_creates_backups` — that called
`apply_kind_rename(plan, dry_run=False)` **without** an isolated
`refactor_log_path=`. `scripts/refactor.py::_append_refactor_log`
then falls back to its module default
`_REFACTOR_LOG = content/.refactor_log.yaml` — the **live tracked
repo file** — appending a no-op `comm-test → comm-new`
`rename-kind` entry on every pytest run. Every sibling test in that
file already passed an isolated tmp `refactor_log_path`; only these
two leaked. The entries are benign (zero real content touched; they
bypass `validate_kind_rename`, which would reject the zero-reference
`comm-test`) but they polluted the working tree on every test run —
silently, across ≥6 commits.

**FIX (this pass):** both calls now pass
`refactor_log_path=seed["content"] / ".refactor_log.yaml"` (the
isolated tmp tree), matching the file's other tests. The live
`content/.refactor_log.yaml` is reverted to its committed state.
**Validation:** after the fix, a full pytest run leaves
`content/.refactor_log.yaml` unmodified in `git status` (recorded in
the re-verify section).
