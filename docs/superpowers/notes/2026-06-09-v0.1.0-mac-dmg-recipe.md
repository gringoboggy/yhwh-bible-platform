### Step 7 — Merge the DMG's SHA-256 into `SHA256SUMS.txt` without clobbering the other lanes' lines

```bash
TAG=v0.1.0
REPO=gringoboggy/yhwh-bible-platform
DMG=dist/YHWH-0.1.0.dmg
BASENAME=$(basename "$DMG")
HASH=$(shasum -a 256 "$DMG" | awk '{print $1}')
gh release download "$TAG" -p SHA256SUMS.txt -O SHA256SUMS.txt --clobber --repo "$REPO" || true
grep -v "  ${BASENAME}\$" SHA256SUMS.txt 2>/dev/null > sums.tmp || true
echo "${HASH}  ${BASENAME}" >> sums.tmp
sort -u sums.tmp -o SHA256SUMS.txt
gh release upload "$TAG" SHA256SUMS.txt --clobber --repo "$REPO"
```

**Note.** This is the self-merge mechanism the Linux CI uses (`.github/workflows/build-linux.yml:61-75`; the merge body is `:71-75`), adapted for macOS (`shasum -a 256` instead of `sha256sum`). It downloads the release's CURRENT `SHA256SUMS.txt` (which may already carry the `.exe`/`.AppImage`/`.epub`/`.kepub` lines from the other lanes), strips only the existing line for THIS basename, appends the fresh one, sorts unique, and re-uploads — so the mac dmg checksum is added **without clobbering the others**. Two-space separator is sha256sum binary-mode format (`<hex>  <name>`). Run AFTER stapling — the staple rewrites the dmg bytes, so the checksum must be computed on the stapled artifact (`NOTARIZATION_STATUS.md:7` / `notary_autofinish.sh:66-67` enforce this ordering). Alternative if you build ALL mac artifacts locally first: `python3 scripts/gen_checksums.py dist --out dist/SHA256SUMS.txt` regenerates from scratch over `dist/`'s `.dmg`/`.exe`/`.AppImage` — but the gh-download-merge path above is safer when the other lanes upload independently.

## Gotchas

- **`build_desktop.sh:43` runs `rm -rf build/ dist/`.** The fresh rebuild (step 3) deletes the ENTIRE `dist/` dir — including the currently-present notarized `dist/YHWH-0.0.3.dmg` and `dist/YHWH-0.0.3-nativewin-TEST.dmg` (both confirmed present in `dist/` today). Move the 0.0.3 dmg to `~/` first if you need the local copy (canonical copy is already on the v0.0.3 GitHub release, so loss is recoverable).
- **`build_dmg.sh:73` does `rm -f dist/YHWH-${VERSION}.dmg`.** The M1 note (`2026-06-08-M1-native-window-verification.md:45-47`) flagged this as a clobber hazard ONLY while `VERSION` is still `0.0.3` — it would wipe the notarized 0.0.3 dmg. **After the 0.1.0 bump (step 1) the rm-f target is `YHWH-0.1.0.dmg`, so the name-clobber is gone** — but the dist-wide wipe in step 3 still happens regardless of version. (This is the `0.0.3`-vs-`0.1.0` filename trap: bump VERSION FIRST, before anything touches `dist/`.)
- **Checksum ordering.** SHA-256 MUST be computed AFTER `stapler staple`, because stapling rewrites the dmg bytes (`NOTARIZATION_STATUS.md:7` "Checksums regenerated AFTER stapling"). Upload the stapled dmg, then hash the stapled file.
- **Use macOS `shasum -a 256`, not Linux `sha256sum`,** when computing on the Mac. The `SHA256SUMS.txt` format is identical (`<hex>  <name>`, two spaces).
- **Do NOT regenerate `SHA256SUMS.txt` from a local `dist/` that lacks the `.exe`/`.AppImage`/`.epub`/`.kepub`** — that would drop the other lanes' lines. Use the gh-download → strip-this-basename → append → `sort -u` → re-upload merge (step 7 / `build-linux.yml:71-75` pattern).
- **No `pywebview[cocoa]` extra exists.** Plain `pywebview==6.2.1` pulls the pyobjc frameworks via PEP 508 markers (`requirements-desktop.txt:14-25`). Writing `[cocoa]` silently does nothing.
- **macOS uses ONEDIR→BUNDLE (`.app`), NOT onefile** (`launcher.spec:145-196`). A onefile inside a `.app` clashes with Gatekeeper/notarization (spec comment `:146-151`); UPX is off for the same reason (corrupts Mach-O signatures, `:211`).
- **The Sparkle appcast is an unused alternate update channel for this release.** The live site upgrades the Latest card from the GitHub Releases API (`releases.js:17-18,:55`); no `appcast.xml` is referenced in `website/`. The release does NOT need an appcast.
- **The GitHub Pages site deploy in step 8 is a live/production publish.** Per the auto-trip guard a "push at discretion" mandate does not auto-authorize a public-site deploy — surface it before running if auto-mode could deny mid-task.
- **v0.1.0 has no tag/release yet** (`gh release view v0.1.0` → not found; `git tag -l v0.1.0` empty). Create it (step 6) or coordinate so the lane that creates the release does so before upload.
