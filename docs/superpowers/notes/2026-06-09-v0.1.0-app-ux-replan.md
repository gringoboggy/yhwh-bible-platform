## ★ S2 attribution-sourcing — DECIDED (2026-06-09, after a drift investigation)

**Decision: source the `.vn-source-byline` by a BUILD-TIME LIVE attribution lookup keyed by
note id, inside `apply_badge_markers`. NO base re-bake.** (Resolves the open §Findings question.)

Why (3-probe investigation, workflow `wf_fac9b66a-9ac`):
- **Drift measured (91,572 baked ↔ live):** kind/aside-class drift = **0** (ids 100% stable,
  attribution present on every matched note) ⇒ a live attribution lookup is **base-consistent**
  for the byline. label drift = **1,370** (baked carries old specific labels e.g. "Hebrew."
  where live was relabeled to generic "Note"); genuine body drift = **only 3** (2ki 4:8, 2ki 11:1,
  gen 14:5f — the other ~1,661 "diffs" are entity-escape/injected-link-whitespace artifacts).
  live-only = 161 (= the known un-baked 1En 37-108 residual).
- **Re-bake REFUTED (HIGH risk):** no clean entrypoint (`inject --all-books` is additive-only via
  the `already_in` guard; `resync rewrite_asides` has no attribution input; bare regen is LOSSY —
  CHANGELOG:1467). It mutates the SHARED base ⇒ breaks "9 KJV byte-identical when flags absent",
  the `build_aside↔rewrite_asides` parity pin (test_resync_markers:280), and the `categorize_diff`
  verifier; forces re-release of all 10 editions. Fights the spec's per-edition-temp-tree architecture.
- **Mechanics:** `fid` (from `id="ref-{fid}"`, already in the loop at build_edition.py:2079) ==
  inject's `{prefix}{cc}{vv}{suffix}`. Build a `{fid: attribution}` index per book inside the
  existing `for book in config.load_books()` loop (mirror `_iter_note_ref_traditions`:128-158;
  `load_notes` is LRU-cached; `config.note_attribution`). Look up per row; no signature change.
- **Residual (3 body-drift notes):** their source is unchanged on a reword ⇒ the byline is correct
  anyway; not worth a per-row body-fingerprint guard. The §4 leaf-conservation guard
  (DISTINCT_OUT==DISTINCT_IN) is the real lossless proof and is implemented.
